## Actual behavior boundary

One bounded, ephemeral read-only Codex CLI run was attempted in isolation. Environment policy prevented that process from reading the target Skill, and the reply acknowledged that limitation. Therefore the run does **not** establish successful Skill invocation; actual first-use behavior remains MANUAL_REQUIRED. Private execution traces are not published.

Native desktop three-chat creation, sender wakeup, real HELLO/ACK exchanges, unfamiliar-user acceptance, and the External Advisor's actual MCP connection are MANUAL_REQUIRED. Running a CLI process does not prove any of those capabilities. The evaluation plan is [REAL-BEHAVIOR-VALIDATION.md](REAL-BEHAVIOR-VALIDATION.md).

## Package/release boundary

The release uses the existing public v0.1.2 mainline as its base, a separate non-forced branch, an unchanged Apache-2.0 license and the runtime allowlist. New files and modifications were checked for credential literals and private absolute paths; none were found. Existing public history and tags are preserved.

After the release tag is pushed, the installation check must obtain that exact tag from GitHub into a fresh isolation directory, run the real installer, compare its version/revision and every file hash, and verify excluded development files are absent. Results of that remote check belong in the GitHub release handoff; this source record does not claim a check that has not yet occurred.

The installation receipt deliberately retains `codex_discovery=NOT_TESTED` and `platform_communication=NOT_TESTED`. Installing the package alone does not authenticate client discovery or communication.

## Existing-project compatibility

Reinstalling a Skill does not migrate project policy. Old event history is retained and reported with LEGACY_EVIDENCE_GAP; new schema-2 tasks can start at a task boundary without rewriting that history. Version/customization checks are read-only. Any explicit migration must preserve user modifications, role bindings and original evidence.

`completed_tasks=0` in the relay checker means that the local checker authenticates **no** task count. It does not mean historical tasks failed; use declared/local-link counts as structural information and independently review real execution evidence.
