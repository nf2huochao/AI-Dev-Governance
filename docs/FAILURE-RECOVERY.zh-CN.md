# 中断或失败后怎么办

优先回到原 Codex 天枢核对话发送：

> 请检查当前项目进度，从已有记录恢复；不要覆盖资料、清空历史或重复创建角色。告诉我现在缺少什么，以及我需要做的一步。

| 你遇到的情况 | 应看到的处理 |
|---|---|
| 路径不存在或打开了错误项目 | 确认正确文件夹；不自动清空或合并两个项目 |
| 安装时已有同名 Skill | 停止覆盖，说明旧版本来源；经你确认后备份到扫描目录之外再更新 |
| 对话已建立但通信无反馈 | 先核实实际创建和收发记录；不反复建角色，不连续查询等结果 |
| 不知道哪个是天枢核 | 核对原项目记录与平台身份；不能靠标题猜测，不能新建替代天枢核 |
| 项目摘要尚未批准 | 返回 ChatGPT 外参师修改；不启动开发 |
| 获批摘要后来修改了 | 保留旧版，说明差异，由你批准新版本，不混用两套需求 |
| MCP 指向其他项目或读不到文件 | 停止独立审查，核对实际连接；不让你粘贴凭据 |
| 本地检查通过，但仍显示需要核验 | 文件只能证明结构一致；需检查真实通信、MCP 读取及用户批准，不是再填写一个 PASS |
| 换了电脑或复制了工作目录 | 先说明迁移来源并核对身份；不能把旧工作区绑定悄悄当成新目录 |
| 已批准摘要或已经开始开发，又被要求从头规划 | 让 Codex 读取已有摘要和当前任务，核对已有批准后继续；不用再次复制同一摘要 |
| 提示角色表或事件历史丢失 | 让 Codex 从版本记录或备份恢复缺失资料；保留现有文件，不重新生成身份或空历史 |
| 更新 Skill 后，原项目还沿用旧提示 | 让 Codex 在当前任务结束后比对新版角色规则，并在已有对话中加载；不覆盖项目记录、不重建角色，不把重新安装当成已完成项目迁移 |

正常接力不需要手动复制 TASK、ACK 或交接。缺少真实回唤能力时自动接力暂停，这是需要说明的限制，不是让用户一直点击“继续”。

开发者执行细节在 [Bootstrap 执行规程](../references/BOOTSTRAP-RUNBOOK.md)，由 Codex 读取；普通用户不需要执行这些内部命令。
